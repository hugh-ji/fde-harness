# CHECKLIST.md — 개인 작업 순서

시간은 180분 작업을 가정한 개인 예시다. 실제 제한 시간·전체 종료 시각·필수 요구가 우선한다. 담당자 이벤트나 채점 기준을 예측하지 않는다.

| 단계 | 경과 예시 | 확인할 사항 |
|---|---|---|
| 1 환경 | 0~10 | 공식 규정·제출 경로·허용 모델 확인, 하네스 출처와 파일 충돌 확인 |
| 2 분석 | 10~15 | 요구·제약·필수 제출물 원문 확인 |
| 3 인터뷰 | 15~40 | 플랫폼 담당자와 실제 대화, 원문·조건 보존 |
| 4 범위 초안 | 40~45 | 필수·선택·제외 범위와 확인 질문 |
| 5 최소 기능 | 45~58 | 미확정 전제 표시, 구현·검증, 합의 상태 구분 |
| 6 계획 | 58~65 | 실측 속도·남은 시간·검증 여유 반영 |
| 7 구현 반복 | 65~130 | 결정·구현·테스트·독립 계산·수동 화면 확인 |
| 8 리뷰 | 130~140 | 실제 요구와 구현 차이 및 근거 |
| 9 수용 확인 | 130~140 | 실제 답변·조건·미합의 사항 기록 |
| 10 입력 검증 | 140~145 | 실제 입력의 오류·경계값과 메시지 |
| 11 인수인계 | 145~155 | 실행·검증·완료·미완·한계를 사실대로 |
| 12 마무리 | 155~160 | 테스트·저장·필수 파일 확인, 기록 보존 |
| 13 직접 확인 | 160~170 | 응시자가 이해·사실 확인, 제출 절차 진행 |

## 컨텍스트 초기화

- 커밋 직후에만 `/compact`. R1 = 합의문 커밋 뒤, R2 = 사용량 30% 넘은 첫 마일스톤 커밋 뒤, R3 = 마지막 마일스톤 커밋 뒤. compact 전에 떠 있는 서버 종료. compact 뒤 첫 요청은 "AGREEMENT·PLAN·DECISIONS 읽고 현재 단계와 다음 할 일", 답이 파일과 맞는지 확인.

## 사용 중 지킬 것

- [ ] 제공 Codex와 공식 허용 모델만 사용한다. Astra·외부 AI·개인 키·개인 구독을 사용하지 않는다.
- [ ] 문제·대화·코드·결과물을 외부 전송·공유·Git Push하지 않는다.
- [ ] 개인 파일 반입·차단 우회·Computer Use·GUI 자동 조작을 하지 않는다.
- [ ] 감독·연결·관리 프로세스를 건드리지 않는다. 오류는 공식 신고한다.
- [ ] UI는 플랫폼 내 미리보기에서 직접 확인하고 실제 확인한 것만 기록한다.
- [ ] 요구·기술 스택·데이터 처리 규칙은 실제 과제 기준으로 정한다.
- [ ] 미회신·조건부 확인을 동의로 바꾸지 않는다. 사후 정리는 시점을 구분한다.
- [ ] 제출물 확정 후 AI를 사용하지 않고 서술형을 직접 입력한다.
- [ ] 최종 제출 완료 화면을 확인한 뒤 종료한다.
